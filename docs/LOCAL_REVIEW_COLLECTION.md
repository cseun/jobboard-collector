# 🖥️ 내 PC Chrome으로 면접 후기 수집하기 (예약)

로그인이 필요한 사이트(캐치·잡플래닛·자소설닷컴·사람인 후기)는 **서버가 아니라 내 PC의 Chrome**이 읽습니다. 내 Chrome에 이미 로그인된 상태를 그대로 쓰므로 **비밀번호를 어디에도 저장하지 않습니다.**

## 흐름
```
예약(내 PC, Claude 데스크톱 앱) ─→ Chrome에서 보드(localhost:18080, SSH 터널) 열기
   ├─ GET  /api/admin/review-targets   오늘 모을 회사(지원 준비 요청 → 내 지원 현황 순, 최대 5곳, 최근 60일 안에 모은 곳 제외)
   ├─ 캐치·자소설닷컴·잡플래닛·사람인에서 후기·합격 자소서·채팅방 글을 읽고 **내 말로 요약**
   └─ POST /api/admin/review-import     회사별로 보드 DB에 덧붙임(기존 글은 그대로, 같은 주소는 한 번만)
```
- 합쳐진 후기는 보드 🎤 면접 후기·모의면접 기출 재료가 되고, 합격 자소서 예시는 📝 서류 준비의 `ex`에 들어갑니다.
- 아무것도 못 찾은 회사도 날짜가 남아 60일 동안 다시 읽지 않습니다.

## 켜 두어야 하는 것 (이게 안 맞으면 그날은 건너뜀)
| 조건 | 확인 |
|---|---|
| PC가 켜져 있고 Claude 데스크톱 앱·Chrome(확장 프로그램)이 열려 있음 | 예약 시각 전 |
| SSH 터널이 열려 있음(`ssh -L 18080:localhost:80 …`) | 브라우저에서 `localhost:18080/board.html`이 열리는지 |
| Chrome에서 캐치·잡플래닛·자소설닷컴·사람인에 **로그인된 상태** | 직접 한 번 로그인해 두기 |
| 보드에 관리자로 로그인된 상태 | `localhost:18080/board.html` |

## 지키는 규칙
- 로그인 화면·결제 안내·캡차가 나오면 **그 사이트는 건너뜀**(입력하지 않음). 비밀번호·결제 정보는 입력하지 않음.
- 채팅방은 **읽기만**(글 쓰기·반응 금지). 다운로드·가입·댓글 작성 금지.
- 후기·자소서 본문을 그대로 복사하지 않고 **요약**(질문 문장은 짧게, 자소서는 제목·연도·스펙 한 줄·구조 포인트·링크만). 작성자 이름 등 개인 정보 제외.
- 회사당·사이트당 후기 최대 10건, 요청 사이 5초 쉼. 막히면(403·429) 그 사이트는 그날 중단.
- 보드 말고 다른 곳으로 데이터를 보내지 않음.

## 예약 프롬프트 (이 문장이 예약에 들어 있음. 바꾸려면 예약을 수정)
```
채용 보드 면접 후기 수집(내 PC Chrome). 아래 순서대로 하고, 마지막에 결과를 짧게 보고해 줘.

0) Claude in Chrome 도구를 불러오고 새 탭에서 http://localhost:18080/board.html 을 연다. 열리지 않으면(SSH 터널이 닫힘) "터널이 닫혀 있어 오늘은 건너뜀"이라고 보고하고 끝낸다.
1) 그 탭에서 javascript로 fetch('/api/admin/review-targets?limit=5',{credentials:'same-origin'}) 를 호출해 JSON을 읽는다. 401/403이면 "보드에 로그인이 필요함"이라고 보고하고 끝낸다(비밀번호는 입력하지 않는다). targets가 비어 있으면 "오늘 모을 회사 없음"으로 끝낸다.
2) targets의 회사마다, 새 탭에서 내 Chrome 로그인 상태 그대로 아래 사이트에서 그 회사의 자료를 찾아 읽는다: 캐치(catch.co.kr: 면접 후기·채팅방), 자소설닷컴(jasoseol.com: 합격 자소서·면접 후기), 잡플래닛(jobplanet.co.kr: 면접 후기), 사람인(saramin.co.kr: 면접 후기). known_urls에 있는 주소는 다시 읽지 않는다. 회사당·사이트당 후기는 최대 10건, 요청 사이에 5초 쉰다.
   - 로그인 화면·결제 안내·캡차가 나오면 그 사이트는 건너뛴다(어떤 것도 입력하지 않는다). 채팅방은 읽기만 하고 글을 쓰거나 반응하지 않는다. 가입·다운로드·댓글 작성 금지.
3) 읽은 내용은 내 말로 요약한다. 후기는 {src(사이트 이름), url, role(직무·연도), flow(전형 흐름), qs(나온 질문, 질문만 짧게), tips(준비 포인트), n(읽은 후기 수)}, 합격 자소서는 {t(제목), y(연도), spec(스펙 한 줄), pts(구조 요약 최대 3개), url, src, login('로그인 필요' 등)}. 원문을 연속 15단어 넘게 그대로 옮기지 않고, 작성자 이름 등 개인 정보는 넣지 않는다. 글자 수 한도: flow·tips 1500자, qs 2500자.
4) 같은 보드 탭에서 javascript로 회사마다 fetch('/api/admin/review-import',{method:'POST',credentials:'same-origin',headers:{'Content-Type':'application/json'},body:JSON.stringify({company, rows:[...], examples:[...]})}) 를 호출한다. 아무것도 못 찾은 회사도 rows:[] 로 호출한다(날짜 기록용). 응답의 "후기 반영"·"예시 반영"을 기록한다.
5) 보드 말고 다른 곳으로 데이터를 보내지 않는다. 마지막에 회사별 반영 건수, 건너뛴 사이트와 이유(로그인 필요·캡차·차단 등)를 표로 보고한다.
```
