# 잡코리아 상세 수집과 검증

## 현재 경로

1. 검색 결과에서 공고 번호, 제목, 회사명, 경력·지역을 읽는다.
2. 새 공고의 상세 페이지를 열고 `iframe[srcdoc]` 안의 채용 본문만 추출한다. 바깥 페이지의 추천공고, 면접 후기, 복지 광고는 본문에 넣지 않는다.
3. 메타 설명의 마감일, 상세 페이지의 작성 회사명과 기업 정보(업종·규모·주소)를 확인한다.
4. 본문에서 담당 업무와 필수 요건을 분리하고, 명백히 관련 없는 직무와 마감 공고를 제외한다. 회사명이 일치하고 회사 업종까지 읽힌 공고만 DB에 저장한다. 우대 사항은 원문에 있을 때만 채운다.
5. 본문이 이미지이거나 별도 로딩되어 글자를 얻지 못하면 저장을 보류하고, 실행 기록에 사유별 건수를 남긴다.

2026-11-27 운영 서버에서 `로봇` 한 쪽(20건)을 시험했다. 신규 후보 9건 중 2건은 이미지, 7건은 업무·필수 구역을 확인하지 못해 저장 0건이었다. **이 결과는 잡코리아 수집이 완성되었다는 뜻이 아니다.** 이미지의 전체 글자 OCR과 항목 분류를 사용자 정답군으로 검증해야 이미지형을 자동 저장할 수 있다. 본문이 없는 텍스트형 화면은 별도 로딩 경로를 추가 조사해야 한다.

## 회사 정보 보강

자동 회사 보강은 접수 중이고 서버 판정이 `×`가 아닌 공고를 대상으로 사람인 기업 번호를 찾고, 회사 페이지의 항목별 정보를 저장한다. 같은 이름의 회사가 여럿이면 자동 확정하지 않는다. 브라우저의 개인별 `숨김` 목록은 현재 서버 DB에 없으므로 회사 보강 대상에서 개인별로 제외할 수 없다.

운영 DB 점검 당시 접수 중으로 분류된 1,470건 중 `회사 정보`가 비어 있는 공고는 1,424건이었다. 자동 보강 한도를 회사 조회 50곳·번호 검색 50곳/일로 늘렸지만, 사람인에 일치하는 회사 정보가 없거나 이름이 모호하면 빈칸으로 남는다. 이미 저장된 공고의 상세 본문·필수·우대는 신규 수집만으로 갱신되지 않으며 별도 재조회가 필요하다.

## 다음 검증

- 대표 이미지의 원본과 사용자 정답 전체 글자를 저장하고 Haiku OCR 결과의 누락·오독을 비교한다.
- 이미지 OCR과 항목 분류를 따로 평가한다. 업무·필수·우대가 원문에 대응하는지 검증한 뒤에만 자동 저장을 허용한다.
- 잡코리아의 본문 별도 로딩 형식을 유형별로 수집한다. 못 읽은 유형은 조용히 빈 정보로 저장하지 않고 실행 기록에 남긴다.
- 기존 접수 중 공고는 신규 수집과 별도 백필에서 상세·회사 정보를 갱신한다. 기존 사용자 수정값을 덮지 않는다.
